# Coachable Robots

An edge-to-cloud pipeline for training robot manipulation policies using imitation learning. Students and makers **coach** a SO-ARM101 robotic arm by demonstrating tasks with an Xbox controller — no programming required.

Demonstrations are recorded as LeRobot datasets, uploaded to HuggingFace Hub, trained on Chameleon Cloud MI100 GPUs, and the resulting policy is pulled back to the robot for autonomous execution.

## How it works

```
┌───────────────────────────┐                          ┌────────────────────────────┐
│    Raspberry Pi 5 (Edge)  │                          │  Chameleon MI100 (Cloud)   │
│                           │                          │                            │
│  Xbox controller teleop   │   HuggingFace Hub       │  LeRobot training          │
│  + SO-ARM101 follower     │  ────── dataset ──────> │  ACT / Diffusion / Pi0     │
│  + 2x USB cameras         │                          │                            │
│  + LeRobot recorder       │  <── checkpoint pull ── │  ROCm 6.3 + PyTorch 2.7    │
│                           │                          │  (gfx908 bare metal)       │
│  Docker container         │                          │  Ansible-provisioned       │
└───────────────────────────┘                          └────────────────────────────┘
        │                                                        │
        └──────────── control node / Jupyter / just ─────────────┘
                    python-chi 1.0+ · Ansible · Tailscale
```

## Data flow

1. **Coach** — Pi runs `lerobot-record` with Xbox controller; episodes saved locally
2. **Push** — Dataset uploaded to HuggingFace Hub (`--dataset.push_to_hub=true`)
3. **Train** — MI100 node pulls dataset by `repo_id`, trains policy, saves checkpoints
4. **Upload** — `hf upload` pushes checkpoint to HF Hub
5. **Fetch** — Pi downloads trained policy (`hf download`)
6. **Deploy** — Pi runs `lerobot-record --policy.path=...` for autonomous execution

## Current operating model

The repo is operated through `just` from a control node. Students and teachers
coach the robot; operators and agents use `just` recipes to keep cloud, edge,
and robot state reproducible.

| Role | Interface | Purpose |
|------|-----------|---------|
| Operator | `just` | Auth checks, CHI@Edge containers, MI100 leases, tests, backups |
| Teacher/student | notebooks and robot session | Coaching demonstrations and interpretation |
| System | python-chi + Ansible | Chameleon leases, provisioning, inventory, node setup |

The active SO-ARM path uses CHI@Edge plus Tailscale:

```bash
ssh root@arm-01
```

Avoid running Balena preview and CHI@Edge robot workloads at the same time. The
Pi has one set of physical cameras and serial ports, and only one container
should own them during a robot session.

## Quick start

For the current end-to-end path, follow
[docs/lerobot-training-session.md](docs/lerobot-training-session.md).

### 1. Check operator state

```bash
just check-env
just check-auth-json
just edge-status
just arm-test
```

### 2. Preserve calibration

Back up the leader/follower calibration before a teaching or training session:

```bash
just arm-calibration-backup label=alpha-current
just arm-calibration-backups
```

### 3. Verify safe robot control

Put both arms in the same relaxed start pose, then run:

```bash
just arm-teleop-safe 30 15
```

This maps wrist roll relative to the matched start pose and clamps follower
wrist roll to +/- 15 degrees to protect the gripper cable.

### 4. Prepare MI100 training

```bash
just reserve
just provision
just test-node
```

Verify the reservation really landed on MI100 hardware before spending a
training window:

```bash
ssh cc@train-mi100 'lspci -nn | egrep -i "AMD|Instinct|MI100|1002"; rocm-smi'
```

### 5. Collect, train, and deploy

Use ACT first. It is the safest MI100 default for this project because MI100
does not support Flash Attention 2. Start with a simple touch task before
pick-and-place.

## Platform support

Recording works on Pi 5 (CHI@Edge and local), Linux laptops, and macOS.
Both SO-ARM100 and SO-ARM101 are supported (SO-ARM101 is a cosmetic update).
See [docs/platform-support.md](docs/platform-support.md) for the full
compatibility matrix of teleop inputs, simulation, and per-platform install.

## Hardware requirements

| Component | Spec |
|-----------|------|
| Robot | SO-ARM101, 6-DOF, Feetech STS3215 servos |
| Edge compute | Raspberry Pi 5 |
| Controller | Xbox controller (via `xbox_soarm_teleop`) |
| Cameras | 2x USB cameras |
| Cloud GPU | AMD Instinct MI100 (gfx908, 32 GB HBM2) |

## MI100 notes (gfx908)

- No Flash Attention 2 (requires gfx90a+) — use **ACT** as the default policy
- No hipBLASLt
- Pi0 3B works with: `--policy.gradient_checkpointing=true --policy.dtype=bfloat16 --batch_size=8`
- Use `rocm-smi`, not `nvidia-smi`
